# 2026-11-02 内核一键安装与保存流程修复

新安装的 RelayDeck 只带原生 TCP/UDP 转发器，不自带 sing-box。此前协议内核页面在缺少该程序时禁用了保存，却没有可直接使用的安装入口；编辑中的启用勾选也可能被轮询恢复成已保存状态。

本次增加：

- 协议内核页的一键安装、阶段与下载字节显示、错误提示和重试。
- 安装成功后自动识别，无需重启；JSON 草稿在安装和轮询期间保留。
- 启用勾选只表达待保存意图，按钮明确显示“校验并保存”或“保存并启用”；成功提示根据实际运行状态显示。
- 保存期间锁定编辑，旧 GET、旧保存响应和已退出会话的响应不会覆盖新状态。
- 停用使用已保存配置，并保留未保存的 JSON 草稿。

安装器使用 Go 标准库，异步执行一个有总时限的任务。下载源固定为官方 sing-box 1.14.4 Release，支持 Linux amd64、arm64、armv7。HTTPS 重定向限定官方主机，SHA-256 固定在程序内；归档最大 64 MiB，二进制最大 160 MiB，只提取精确匹配的普通文件。不会接受用户提交的 URL。

内核先写入数据目录下的私有临时目录，校验版本后使用硬链接原子发布到 `engines/sing-box`，拒绝覆盖已有文件。关闭管理器会取消任务、等待结束并清理该任务的临时文件。有效的系统 PATH 内核优先；系统内核缺失或无法执行时继续尝试私有内核。显式指定其他内核路径时不支持面板安装。

安装 API 受会话、CSRF 和同源检查保护，只接受空 JSON 对象。安装本身不保存配置或启动模板。现有系统内核、管理认证、转发配置、证书及权限限制保持原有管理方式。

验证记录：

- 本地 Go 全包测试和 vet 通过。
- Linux 安装回归验证了归档篡改拒绝、精确提取、重定向限制、单任务、失败重试、大小限制、关闭取消及临时文件清理。
- 隔离 Linux 面板经受保护的 API 实际下载官方 Release，然后校验保存、启用、真实 TCP/UDP 回显、停用及再次启用，通过。
- 同一真实下载与启用测试在现有生产 systemd 的权限、系统调用及文件系统沙箱限制下通过，使用独立临时数据目录，现有服务保持正常。
- GPT-6 Astra 只读复审发现损坏的 PATH 内核可能遮蔽私有安装；已改为逐项执行探测，并补充完整安装回归，保留系统文件原字节及有效系统内核优先。

真实外部下载测试需要明确设置 `RELAYDECK_TEST_DOWNLOAD=1`。浏览器交互使用受控 API 状态验证安装进度和失败，不把 mock 作为真实下载证据。可复现命令见 [verification.md](verification.md)。
