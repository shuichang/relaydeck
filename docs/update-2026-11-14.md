# v0.1.7：双栈目标转发与证书文件路径修复

本次版本针对低配置 VPS 的透明 L4 转发路径做了收敛：

- 目标地址支持 IPv4、IPv6 字面量和解析到两种地址的主机名。
- TCP 根据目标地址族使用 `tcp4` 或 `tcp6`；UDP 根据目标地址族使用 `udp4` 或 `udp6`。
- 保留 IPv4/IPv6 入口之间的透明互转：IPv4→IPv4、IPv4→IPv6、IPv6→IPv4、IPv6→IPv6。
- UDP 目标返回 `connection refused` 时，错误会明确说明目标 UDP 端口未监听或主动拒绝；UDP 只有收到真实目标回包才恢复。
- 规则页面把“当前仅 TCP、历史来自 UDP”的记录标成“历史错误（UDP）”，并说明它不影响当前 TCP。
- 服务器文件证书错误包含实际路径和服务进程可读性提示。安装器使用 `ProtectHome=tmpfs`，仅通过 `BindReadOnlyPaths` 开放 `/root/cert` 与 `/root/.acme.sh`，不会让 RelayDeck 读取整个用户目录。
- 目标探测延迟标明实际使用的 IPv4 或 IPv6 地址。探测仍只代表中转机到目标的 TCP 握手，不代表协议认证或最终业务可用。

协议边界保持不变：RelayDeck 继续按字节透明转发 VLESS、Reality、XHTTP、Hysteria2、TUIC、TLS、SSH 等 TCP/UDP 流量，不解析这些协议。联网复核后文档推荐在兼容端点上优先考虑 XHTTP；当前内置 sing-box 1.14.4 模板集不含 XHTTP 模板。

- 四种 TCP 地址族组合和四种 UDP 地址族组合的真实本地回显
