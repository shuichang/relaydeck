# v0.1.3 转发体验与资源优化

## 行为变更

- 新建规则默认连接上限为 8192，`0` 也采用 8192；可配置上界为 65536。已有显式值（包括 256、4096）保持原值。TCP 连接及 UDP 会话分别受该规则的上限约束。
- 新建和编辑弹窗可在保存前检测入口和目标，规则列表也可逐条重新检测。保存后自动检测一次，无全规则后台轮询。
- 入口展示本机监听状态或端口可绑定性，不向业务入口发送测试连接、不占用转发配额。端口可绑定不代表已启用或公网防火墙已放行。
- 浏览器到面板的耗时单独标为 HTTP 往返；目标延迟为中转机到解析后 IPv4 的 TCP 握手，不含 DNS，也不证明认证、隧道远端或最终服务可用。UDP 显示未验证，不生成虚假毫秒值或发送随机协议数据。
- 检测结果关联规则参数；编辑、启停或关闭弹窗会使旧结果失效，取消的异步请求不能覆盖新草稿。界面显示活动连接数、有效上限及接近/达到上限的提示。
- 可选内核新增首项通用 TCP/UDP 直连模板。Reality 模板取消入站及出站仅 TCP 的限制，明确使用 XUDP；UDP 需要远端兼容。普通转发规则仍按 TCP/UDP 原样转发，无须启动 sing-box。
- TCP 复制隐藏 `TCPConn.WriteTo`，确保实际使用现有的 8 KiB 缓冲池，避免计数 writer 使快速路径退回额外的 32 KiB 缓冲分配。

应用新版模板会替换编辑器内配置，需要填写自己的地址和认证参数。升级不会自动改写已保存的规则、协议内核配置、管理员认证或证书。已有 TCP-only 内核配置不会因模板更新自动获得 UDP 支持。

## 验证

本地 `go test ./...`、`go vet ./...` 通过。Linux 独立测试二进制通过原生转发、诊断、HTTPS API、内核管理及十份官方内核配置检查。

真实浏览器回归通过保存前检测、目标拒绝、修改后旧响应丢弃、保存后自动检测、TCP/UDP 实际回显、纯 UDP 上限告警、65536 配置持久化，以及桌面和 390px 手机布局。浏览器无脚本异常、手机无页面横向溢出。另以受控响应顺序验证列表旧成功不能覆盖编辑框新失败，列表旧 HTTP 错误也不能覆盖新成功。

真实 sing-box 1.14.4 测试通过：

- VLESS、VLESS + Reality、Hysteria2 各自经 IPv4/IPv6 原生转发到 IPv4，六条链路。
- 通用直连及 Reality/XUDP 两份实际模板分别经 IPv4/IPv6 入口承载普通 TCP 字节及 UDP 报文，八条回显链路。

1500 条并发 TCP 连接保持打开并完成逐条回显，在同一 VPS 上对当前前一版本与本版运行同一基准：

| 指标 | v0.1.2 | v0.1.3 |
| --- | ---: | ---: |
| 同时保持的 TCP 连接 | 1500 | 1500 |
| 每连接保留堆 | 85,692 字节 | 20,191 字节 |
| 相对下降 | — | 约 76.4% |

保留堆含同一测试进程中的转发器、客户端和回显目标，不是 RSS 或内核 socket 内存，也不保证其他负载下比例相同。可配置连接上限不会预分配全部会话；真实容量仍受 VPS 内存、文件描述符和目标服务限制。默认 systemd 文件描述符上限为 65535，TCP 转发每会话至少占用两个描述符，高配置值需要据实际资源调整。

## GPT-6 Astra 独立审查

审查共发现三项 P2：

1. 对监听端口发起入口握手会触发真实转发，静默上游和半关闭可能占用配额。已改为只检查自身监听状态；新增单连接配额及静默目标回归。
2. 草稿临时绑定可能在规则替换期间抢占端口并影响回滚。已让所有权检查、临时绑定和释放协调使用规则生命周期锁，等待可取消；新增取消和端口释放回归。
3. 列表和编辑框共用的检测缓存可能被较早请求的迟到结果覆盖。已统一同一参数 key 的全局请求序号，成功与错误路径均只接受最新请求；退出登录后清理缓存并使旧请求失效。两种跨视图乱序浏览器回归均通过。

GPT-6 Astra 最终复核确认三项 P2 均已关闭，未发现新增 P1/P2。TCP 缓冲改动保留流量计数、半关闭、取消及错误处理。公开的 `scripts/test-web.cjs` 和 CI 会持续验证浏览器操作及两种跨视图乱序路径；发布验收结果以对应提交和 GitHub Actions 记录为准。

## 安装脚本的地址识别修复

另一台 Debian VPS 首次安装时报告 `could not detect the public IP`。旧脚本只请求一个外部 HTTPS 服务，8 秒未取得响应即终止，没有读取网卡上已有的公网地址；该报错不能据此证明主机没有公网 IP。

安装脚本现已改为显式入口覆盖优先，其次读取本机 IPv4 路由/网卡，再读取本机 IPv6；没有合适的本机地址时，按地址族使用多个 HTTPS 备用服务。外部请求设有 2 秒连接、4 秒总超时及响应大小限制，绕过代理、限制 HTTPS，丢弃失败传输的残片和无效/保留地址。仍无法识别时会给出把 `RELAYDECK_PUBLIC_IP` 传给管道右侧 `bash` 的完整重试命令。

独立回归包含 88 项检查，在 Git Bash 和 Linux 均通过；Linux 实测禁用全部外部 IP 请求后仍能从本机识别公网地址。GPT-6 Astra 审查未发现 P1/P2，另验证 IPv6 压缩、IPv4 尾部及畸形输入。该修复位于 `main/scripts/install.sh`，无需重新发布 v0.1.3 二进制；已有完整证书与认证不重新探测或重建。
