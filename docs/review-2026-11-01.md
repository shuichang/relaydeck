# 核心功能审查记录

按用户要求，由 GPT-6 Astra 对 `e355ef1` 的核心代码进行独立只读审查；修复由原 Go 开发分工完成，再交同一审查代理增量复核。

初审发现 1 项 P1、3 项 P2，无 P0。增量复审结论：Linux 发布范围内四项均可关闭，未发现补丁引入的新阻断问题。

| 级别 | 初始问题 | 修复与验证 |
| --- | --- | --- |
| P1 | UDP 通配监听回包未保存本地目的地址，多 IP 主机可能从错误源 IP 回复 | Linux 使用接收 packetinfo，保存本地地址、接口及控制消息族；发送时显式指定源地址，会话键包含目的地址与接口。Debian 13 上验证 IPv4 两目的地址、双栈和指定 IPv6 回包及会话隔离。 |
| P2 | 请求体未超限，但格式化或合并后的配置文件超过加载上限 | 统一检查最终序列化内容；两个配置 API 都在改变运行状态前检查完整配置大小，保存层再次防守。覆盖缩进膨胀、两部分配置合并超限、拒绝后旧文件不变及缩减配置后的恢复。 |
| P2 | 进程短周期崩溃会重置自动重启次数 | Manager 保存跨进程的连续故障预算，依次退避 1/2/4/8/16 秒，最多五次自动重启。稳定运行 60 秒或成功手动应用配置后复位。测试覆盖连续多次启动后崩溃及稳定窗口。 |
| P2 | 安装器可能把其他 HTTPS 服务的健康响应当成安装成功 | 连续检查目标 unit、稳定 MainPID、端口监听归属、HTTP 200 及服务名和版本身份；失败恢复旧二进制与 unit。隔离测试使用临时 Go HTTPS 服务和随机回环端口。 |

修复阶段还移除了安装归档检查中会提前关闭管道的命令，避免 `pipefail` 下出现 `tar` 的 SIGPIPE 错误。

审查代理独立执行了四个核心包测试、vet，以及 forward 的 Linux amd64、arm64、armv7 测试二进制交叉编译。目标 Debian 13 的 packetinfo 实测由主代理执行；审查代理没有独立执行多网卡、策略路由或 ARM 实机测试。

非 Linux 平台仅保留开发及普通回环测试用途，其通配 UDP 回包源地址保留能力有明确限制。正式产品发布范围为 Linux。完整可重复测试方法见 [verification.md](verification.md)。
